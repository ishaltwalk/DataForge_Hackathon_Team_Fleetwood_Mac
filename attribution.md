# Syllable attribution study

Generated by `python scripts/attribution_study.py`. No audio, no
network, no API keys. Deterministic: the same command produces the
same numbers on any machine with the repository checked out.

## Method

For every word in the committed bank, one phone in one syllable is
replaced with a substitution a real learner makes (th to s, r to l,
v to w, tense to lax vowels, and so on), one syllable at a time. The
resulting phone sequence is fed to the shipped scorer.

Only the microphone is stubbed. The alignment, the articulatory
distance, the syllable attribution and the pass threshold are the
same code the running app uses. The blamed set is read from
`core.correct.wrong_syllables`, which is both what the UI highlights
and what `build_correction` brackets for Rime, so this measures
user-visible behaviour rather than an internal proxy.

Each word is first scored on its correct pronunciation. A word that
fails its own control is excluded and counted as a false alarm,
because sabotage results for it would be meaningless.

## Results

Word bank: **5000 words**, of which **5000** contain at least one substitutable phone.
Per-syllable cost threshold: `0.05`.

| Measure | Count | Rate |
|---|---|---|
| Sabotages tested | 19229 | |
| Detected as a failure | 10190 | 53.0% |
| **Correct syllable blamed, of those detected** | **10190 / 10190** | **100.0%** |
| Misattributed (blamed the wrong syllable) | 0 | 0.0% |
| Undetected (substitution too small to trip the gate) | 9039 | 47.0% |
| False alarms on correct pronunciation | 0 | 0.0% |

### Reading these

**The bolded row is the claim.** Detecting that something was wrong
is the easy half, and a tool that failed every attempt would score
100% on detection while being useless. The product claim is that the
syllable it points at is the syllable the speaker actually broke.

**Undetected is under-sensitivity, and is the expected trade-off.** A
substitution one articulatory feature wide is genuinely close to the
target. `core/score.py` documents why the syllable-level gate carries
the pass decision rather than the overall score, and these are the
cases that sit just under it. They are counted here rather than
dropped, because a study that hid them would be measuring the wrong
thing.

**Misattribution is the serious failure.** It means the app pointed
at a syllable the speaker got right, and Rime then enunciated the
wrong sound. That is why it is reported separately instead of being
blended into a single accuracy figure.

## What this does not show

This study starts from a phone sequence, so it does not exercise the
microphone, the browser's audio conversion, or Whisper. Those are
covered by `tests/acceptance.py`, which runs the whole path against
committed recordings. Read the two together: this one shows the
scoring generalises across the bank, that one shows it survives real
audio.

It also assumes a learner substitutes one phone cleanly. Real
mispronunciation is messier: timing drifts, syllables get dropped
entirely, stress lands wrong. Dropped syllables cost far more than a
substitution and are correspondingly easier to attribute, so the
numbers here are the pessimistic end of the range rather than the
flattering one.
